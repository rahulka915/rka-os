# RKA OS Project Rules

- **Initialization Check**: Every time you start a new conversation or take over this project, you MUST read `.agents/CONTEXT.md` to understand the architecture and `.agents/ROADMAP.md` to understand the current goals.
- **Check & Deploy Policy**: Always verify changes by running `npx tsc --noEmit && npm run build` locally to catch errors. Once verified, always commit and push the changes so that they deploy to Vercel.
- **CRITICAL - Changelog Maintenance**: You MUST use the `deploy-with-changelog` skill whenever you are ready to push code. This ensures the `VersionHistoryModal` is correctly updated with the local time and exact changes. Do not push code without invoking this skill.

## Lessons Learned & Mistakes to Avoid
- **iOS Edge-to-Edge Layout**: When building iOS PWA layouts, do NOT use flexbox to "box in" the scroll area between the header and footer. Instead, use an absolute overlay system (`position: absolute; inset: 0`) for the scroll container, and float the navigation bars over it (`position: absolute; top: 0` / `bottom: 0`) with `backdrop-filter: blur`. This ensures the content bleeds underneath the glass bars like a native app.
- **Apple HIG Dimensions**: Native iOS navigation bars are very compact. Use `44px` for top headers and `49px` for bottom tab bars (plus safe areas). Do not use thick 1px borders; use `0.5px` transparent box-shadows.
- **Glassmorphism Blur Issues**: If a scrolling container (like PullToRefresh) has an opaque background (e.g., `backgroundColor: var(--rka-bg)`), it will cover the background behind the glass bars, making the blur effect fail. The glass blur only works if the glass bar has different colored content scrolling underneath it. Ensure the scroll area has the correct `padding-top` and `padding-bottom` to clear the absolute bars.
- **Safe Area Padding Box Model Bug**: When adding `padding-bottom: env(safe-area-inset-bottom)` to a bottom tab bar that already has a fixed `height`, you MUST include `box-sizing: border-box`. Without it, CSS `content-box` will add the safe area padding ON TOP OF the height, causing the tab bar to double in size on notched devices.
- **Safari Flexbox Center Bug**: Even with `box-sizing: border-box`, Safari has a notorious bug where `align-items: center` calculates its center based on the *total box size* (including padding) rather than the content box. This causes items to float too high when `padding-bottom` is applied. To bypass this, NEVER set an explicit `height` on a flex container with `padding-bottom`. Instead, set the height on the children (`height: 49px`) and let the container wrap them naturally.
